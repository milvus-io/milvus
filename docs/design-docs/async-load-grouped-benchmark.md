# ASYNC_LOAD 分组队列复测（2026-11-13）

## 结果

已将逐任务堆改为按 `(priority, load_seq)` 分组的就绪堆，每组使用 Folly 并发 FIFO。保持严格的组选择顺序，未引入分片、序号档位映射或批量取任务。executor 适配器在创建时绑定组，普通组内入队不获取调度锁；组切换才调整堆。

相对旧堆，深队列零工作量场景吞吐约为旧版的 4.1 倍，10 μs 场景约为旧版的 1.8 倍。100 μs 场景基本持平；单线程零工作量场景的中位吞吐约低 8%，且存在波动，分组并非所有场景都更快。分组版本仍低于 Folly 默认 FIFO，不能宣称调度开销已经消除或已经具备生产性能验收结果。

## 纯队列吞吐

16 个线程反复出队再入队，每次操作是一对 dequeue/enqueue。任务数保持在 [深度−16, 深度]，上下文预建。新版本额外预绑定对应组，体现生产适配器持有组的热路径，不将每次查注册表计入普通入队；冷建组成本另计。

| 深度 | Folly FIFO（百万对/秒） | 旧堆（百万对/秒） | 分组（百万对/秒） | FIFO p99 | 旧堆 p99 | 分组 p99 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 64 | 4.343 | 0.631 | 0.884 | 12.34 μs | 83.65 μs | 64.71 μs |
| 4096 | 4.342 | 0.202 | 0.885 | 12.49 μs | 355.18 μs | 68.76 μs |

新 raw harness 为两种优先级分别准备上下文（共 2048 个），旧二进制共 1024 个；序号分布、优先级分布、任务数量和并发数相同。Folly 与分组版本使用同一新 harness。该变化避免把每次绑定组的冷路径混入分组版本，但原始队列结果不是逐指令完全一致的对照。执行器任务链基准的每链绑定策略和任务工作量保持一致。

## 正确性与生命周期

- 就绪位和未预留任务数使用同一个原子字。消费者选择组时预留一个任务，最后一个预留同时清除就绪位；FIFO 真正取任务在调度锁外进行。调度锁定义严格的组选择顺序，多 worker 的执行或完成顺序仍不作保证。
- 生产者等待锁后重新检查计数和就绪位，避免另一个生产者发布、消费者取空之后，迟到的生产者把空组重新放入堆。早期并发冒烟测试复现过这个问题，修复后该测试及重复压力测试通过。
- 同 key 的适配器共享组。RequestContext 仅保存弱组引用，避免队列→任务上下文→组形成强引用环；失效或跨队列引用按数值序号重新绑定。注册表弱条目随组析构删除。队列销毁时显式清空待执行回调，再释放组引用，处理回调持有适配器/组的引用环；对应检查先复现失败，修复后通过。
- 建组时提前预留就绪堆容量；FIFO 任务提交后发布组不需要额外分配堆向量。组销毁和 FIFO 清理在调度锁外进行。
- 每组 FIFO 使用 16 项分配段。当前构建 `sizeof(CPUTask)=128`、`sizeof(LoadTaskGroup)=256`，起步成本至少包含 2048 B 任务槽位和 256 B 组对象，此外还有段头、同步状态、shared_ptr 控制块和注册表节点。1 万个活跃组仅这两项至少约 22 MiB；不是零成本分组。就绪堆向量保留历史峰值容量。

## 验证结果

- 9 项定向测试随机顺序重复 10 轮通过，包括排序/同键 FIFO、协程恢复、跨 executor 切换、线程池缩容、独立适配器同组 FIFO、并发提交和空组反复激活。并发测试累计检查 1,310,720 个 callback 各执行一次。
- 独立检查覆盖：带未执行任务的队列销毁、payload/组释放、弱注册表清理、过期上下文、跨队列上下文以及空队列超时。每次基准运行前执行检查。
- ASan + UBSan（开启泄漏检测）完成 16 并发、深度 64/4096 的纯队列和 executor 四个场景，无错误报告。Folly 等外部共享库未重新插桩，覆盖范围不能等同于全量 sanitizer 构建。
- ThreadSanitizer 本机不可用；最小独立 std::thread 程序也报 `FATAL: ThreadSanitizer: unexpected memory mapping`。不声称 TSan 通过。
- 最终代码（包含待执行回调清理修复）的正式性能复测 135 次均退出 0，原始 CSV 每场景/变体各 5 条，无缺失。clang-format 和 git diff --check 通过。
