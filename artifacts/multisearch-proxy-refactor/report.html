Milvus native MultiSearch · Proxy ownership refactor · 1 November 2026

One Proxy, one existing Search execution path

Server.MultiSearch now delegates to Proxy.MultiSearch. The separate MultiSearchExecutor type and its Server field have been removed. The existing DQL scheduler still executes every child search.

What changed: batch coordination and shared admission state now belong to the existing Proxy. The shared Search entry callback terminates directly at Proxy.Search. There is no child call back through Server.Search, no new serving endpoint, and no replacement search worker pool.

1. Integration: thin transport, Proxy-owned coordination

The public service and Python method are unchanged: MilvusClient.multi_search sends one MilvusService.MultiSearch RPC containing independent SearchRequest items. Each item chooses its own database, collection and parameters; results remain independent and ordered.

func (s *Server) MultiSearch(ctx context.Context, req *milvuspb.MultiSearchRequest) (*milvuspb.MultiSearchResponse, error) {
    return s.proxy.MultiSearch(ctx, req)
}

The parent and its bounded dispatch goroutines stay outside the DQL worker pool. Only existing SearchTasks enter the queue. Waiting parks Go goroutines but retains state; executing tasks still occupy logical pool slots while waiting for QueryNodes. Admission limits bound pressure without establishing priority or reserving ordinary-Search capacity.

2. Keep ordinary Search entry checks

Calling Proxy.Search directly does not run gRPC interceptors. During startup, the transport installs the same Search entry chain used by ordinary RPCs. Its terminal handler calls the existing Proxy component directly. The chain preserves database normalization, authentication, per-collection RBAC, quota checks, hooks and independent request statistics.

func newMultiSearchEntry(component types.ProxyComponent, limiter types.Limiter, getMetaCache func() proxy.Cache) func(context.Context, *milvuspb.SearchRequest) (*milvuspb.SearchResults, error) {
    entry := proxyEntryInterceptor(limiter, getMetaCache)
    return func(ctx context.Context, req *milvuspb.SearchRequest) (*milvuspb.SearchResults, error) {
        // Fork mutable stats; the access-log interceptor similarly allocates
        // an independent object. Identity, deadlines and tracing are inherited.
        ctx = metrics.WithIndependentRPCStats(ctx)
        resp, err := entry(ctx, req, &grpc.UnaryServerInfo{Server: component, FullMethod: milvuspb.MilvusService_Search_FullMethodName},
            func(ctx context.Context, req any) (any, error) {
                return component.Search(ctx, req.(*milvuspb.SearchRequest))
            })
        if err != nil {
            return nil, err
        }
        result, ok := resp.(*milvuspb.SearchResults)
        if !ok || result == nil {
            return &milvuspb.SearchResults{Status: merr.Status(merr.WrapErrServiceInternalMsg("Search entry returned an invalid response"))}, nil
        }
        return result, nil
    }
}

Installation happens once. The callback is published atomically after limits and shared channels are initialized. A second installation cannot reset permits while work is active. Before installation, MultiSearch returns a retriable ServiceNotReady status; there is no unchecked Search fallback. Active batches inherit both the request deadline and cancellation of the Proxy component context.

3. Actual dispatch through the existing path

Excerpt from Proxy.MultiSearch, after validation and batch admission. The callback below performs entry checks and invokes ordinary Proxy.Search, which constructs and enqueues its existing SearchTask.

// The RPC handler and these bounded workers stay outside the DQL pool.
for range min(parallelism, len(req.Items)) {
    wg.Add(1)
    go func() {
        defer wg.Done()
        for ctx.Err() == nil {
            i := int(next.Add(1) - 1)
            if i >= len(req.Items) {
                return
            }
            select {
            case node.multiSearchActive <- struct{}{}:
            case <-ctx.Done():
                return
            }
            if ctx.Err() != nil {
                <-node.multiSearchActive
                return
            }
            item := req.Items[i]
            // Search and entry interceptors may mutate the request. Never share
            // caller-owned request pointers between workers (or retry attempts).
            search := proto.Clone(item.Search).(*milvuspb.SearchRequest)
            result, err := (*entry)(ctx, search)
            <-node.multiSearchActive
            outcome := &milvuspb.SearchOutcome{Id: item.Id, Result: result}
            if err != nil {
                s := status.Convert(err)
                outcome.Result = nil
                outcome.GrpcCode, outcome.GrpcMessage = int32(s.Code()), s.Message()
            } else if result == nil || result.Status == nil {
                outcome.Result = &milvuspb.SearchResults{Status: merr.Status(merr.WrapErrServiceInternalMsg("Search returned no result status"))}
            }
            // Reserve protobuf framing overhead as well as outcome bytes.
            if resultBytes.Add(int64(proto.Size(outcome)+16)) > int64(node.multiSearchLimits.MaxResponseBytes) {
                overflow.Store(true)
                cancel()
                return
            }
            out.Items[i] = outcome
        }
    }()
}
wg.Wait()

Caller-owned requests are cloned before entry processing. Each child acquires a shared permit until its Search call returns. Item status or transport errors are recorded independently. A deadline or aggregate response-size overflow fails the unary envelope, as before. Permit release does not prove all downstream work has already stopped after cancellation.

5. Fresh mixed-traffic measurements on this binary

128 ordinary Search workers first saturate a two-CPU standalone server. A second client then adds 480 logical searches/s, using either eight concurrent Search RPCs or one eight-item MultiSearch RPC. The resident client continues through baseline, injection and recovery. Two repetitions use opposing API order; each run has 5 s warmup, 15 s baseline, 30 s injection and 15 s recovery. Steady-state statistics exclude the first three seconds of each phase.

This repeats the resource-contention check on the new binary; it is not a matched before/after measurement proving the ownership refactor improves performance. The earlier stock-v3.0.5 comparison and 14-run mixed-traffic report remain historical evidence for their recorded binary.

The fixture uses eight FLAT collections across two databases, nq=1, topK 5–8, dimensions 128/192/256, L2/IP/COSINE and bounded tmpfs storage. GOMAXPROCS remains four. Benchmark admission limits are 128 shared children/32 batches, above defaults of 64/eight. The shared host and short runs do not establish tenant fairness, production latency, PSC resilience or long-term stability. No confidence intervals are claimed.

Unpublished protocol and SDK companion patches are still required. The failure-path audit and raw measurements accompany this report. Previous reports are explicitly labeled historical. The PR's primary report now describes this Proxy-owned implementation.
