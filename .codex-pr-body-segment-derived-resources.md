## Summary

Bind segment-derived query resources to the same immutable published state as schema, load metadata, skip indexes, and field readiness.

This change:

- moves geometry caches and TEXT LOB reader handles into the segment runtime resource snapshot;
- publishes replacements and drops as a new state generation while old snapshots keep their resources alive for in-flight reads;
- replaces the capacity-limited TextColumnCache with a weak, path-keyed registry of reference-counted shared readers;
- includes the published query-state generation in expression-cache identity and threads captured state through expression paths that access derived resources;
- preserves structured TEXT storage failures through the segcore boundary and classifies permanent and transient storage codes in merr;
- updates the TEXT LOB design document and adds lifecycle, concurrency, snapshot, and error-classification coverage.

## Root cause

Published segment metadata already used copy-on-write state, but geometry caches and TEXT readers lived outside that state. Reopen or drop could therefore expose mixed generations to one operation, and resource lifetime followed mutable cache behavior instead of the data snapshot that a query had captured.

The previous TEXT reader cache also coupled reader lifetime to an arbitrary capacity limit. A reader could be evicted independently of whether segment data still referenced it, while many segments pointing at one partition-level LOB path could not express shared ownership directly.

## Behavior after this change

- A captured published segment state owns the derived resources it references.
- Reopen, replacement, and field drop publish a new generation; an older generation remains usable until its last reader releases it.
- TEXT readers are shared by LOB path, initialized lazily, serialized per underlying reader, and released when the final owning segment state disappears.
- Reader count follows loaded data rather than a max-file-readers capacity setting.
- Expression result cache entries do not cross published query-state generations.

No public API or wire-format change is introduced.
